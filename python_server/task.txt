## Tier 1: Planner Agent

The PlannerAgent must:

1. Receive:

   * `user_input`
   * `parameters`

2. Analyze the request.

3. Determine which domain workers are required.

4. Create a structured execution plan.

5. For every worker, generate:

```json
{
    "agent_name": "InventoryAgent",
    "task": "Analyze current inventory and determine reorder requirements.",
    "parameters": {
        "current_stock": 100,
        "warehouse_capacity": 500
    }
}
```

6. The Planner must only plan tasks. It must not perform domain analysis.

7. The Planner must be able to receive a failed validation result and generate a corrected task assignment for the specific failed worker.

Example retry request:

```json
{
    "agent_name": "InventoryAgent",
    "original_task": "Analyze inventory",
    "previous_output": {},
    "validation_feedback": [
        "Warehouse capacity was not analyzed",
        "The reorder recommendation is missing"
    ],
    "attempt": 2
}
```

The Planner should return:

```json
{
    "agent_name": "InventoryAgent",
    "task": "Re-analyze inventory including warehouse capacity and reorder requirements. Ensure both metrics are explicitly included.",
    "parameters": {
        "retry": true,
        "attempt": 2
    }
}
```

## IMPORTANT: Parallel Execution

The workers must NOT run sequentially.

Do NOT do:

```python
for agent in agents:
    result = await agent.run()
```

Instead, execute independent workers concurrently using:

```python
asyncio.gather()
```

Example:

```python
results = await asyncio.gather(
    inventory_agent.run(...),
    logistics_agent.run(...),
    finance_agent.run(...),
    sales_agent.run(...)
)
```

Only execute agents selected by the Planner.

The Planner may select one or multiple workers.

If the Planner selects:

```text
InventoryAgent
LogisticsAgent
FinanceAgent
```

then all three must execute concurrently.

## Tier 3: Validation Agent

Create a dedicated:

```python
ValidationAgent
```

The ValidationAgent must also use Google ADK `LlmAgent` with Groq through LiteLLM.

Its responsibility is NOT to redo the domain task.

It must validate whether the worker output correctly satisfies:

1. The original user request.
2. The Planner's assigned task.
3. The assigned parameters.
4. Required domain-specific metrics.
5. Correct usage of available tool results.
6. Output completeness.
7. Internal consistency.
8. No hallucinated or invented data.
9. Valid recommendation.
10. Confidence value.

The ValidationAgent should return:

```json
{
    "agent_name": "InventoryAgent",
    "valid": true,
    "score": 0.95,
    "issues": [],
    "missing_requirements": [],
    "feedback": "The worker correctly analyzed inventory, capacity, optimization and reorder requirements."
}
```

For invalid output:

```json
{
    "agent_name": "InventoryAgent",
    "valid": false,
    "score": 0.55,
    "issues": [
        "Warehouse capacity was not analyzed",
        "Reorder recommendation is missing"
    ],
    "missing_requirements": [
        "warehouse_capacity",
        "reorder_recommendation"
    ],
    "feedback": "The worker must rerun the inventory analysis and explicitly include warehouse capacity and reorder recommendation."
}
```

## Validation Must Be Parallel

Validation of independent workers must also happen concurrently.

For example:

```python
validation_results = await asyncio.gather(
    validation_agent.validate(inventory_result),
    validation_agent.validate(logistics_result),
    validation_agent.validate(finance_result)
)
```

Do not validate workers one by one.

## Retry Logic

Implement a maximum retry count:

```python
MAX_ATTEMPTS = 10
```

Each worker must have its own attempt counter.

Example:

```python
attempts = {
    "InventoryAgent": 1,
    "LogisticsAgent": 1,
    "FinanceAgent": 1
}
```

If validation succeeds:

```text
Worker → Validation PASS → Mark as completed
```

If validation fails:

```text
Worker → Validation FAIL
       ↓
PlannerAgent
       ↓
Generate corrected task
       ↓
Same specific worker
       ↓
ValidationAgent
```

Only retry the failed worker.

Do NOT rerun successful workers.

Example:

```text
InventoryAgent → PASS
LogisticsAgent → FAIL
FinanceAgent → PASS

Retry only:

LogisticsAgent
```

The retry loop should continue until:

```text
Validation PASS
```

or:

```text
attempt == 10
```

Use a structure similar to:

```python
while failed_agents and attempt < MAX_ATTEMPTS:
    ...
```

Each worker should have an independent retry count.

Do not allow one failed worker to block successful workers.

## Important Retry Requirement

When a worker fails validation, send the following information back to the Planner:

```json
{
    "agent_name": "LogisticsAgent",
    "original_task": "...",
    "parameters": {},
    "previous_output": {},
    "validation_result": {},
    "attempt": 2
}
```

The Planner must generate a corrected task.

Then execute only that worker again.

The retry process should be:

```text
Validation Failure
       ↓
Planner receives failure details
       ↓
Planner creates corrected task
       ↓
Specific Worker executes again
       ↓
Validation Agent validates again
       ↓
PASS → completed
FAIL → retry
```

Maximum 10 attempts per worker.
